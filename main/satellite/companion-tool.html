Dual-Stack Companion Tool

tools/dual-stack-companion.py is a host-side Python script that provisions a dual-stack device over Bluetooth LE.

The sat-dual-stack samples all wait for this tool on boot. These samples won’t beacon to either terrestrial or satellite networks until this tool has provisioned the device.

Important

The samples do not persist the provisioning data across power cycles. The data is stored in RAM only, so the device must be re-provisioned after every power cycle.

Purpose

A satellite is only overhead for a few minutes at a time. To save power, a dual-stack device predicts the next pass with hubble_sat_next_pass_get() and keeps its satellite radio off until then. That prediction uses Unix time, the device’s location, and the satellite’s orbital parameters to calculate visible passes.

In a product, provisioning would be done by a phone app, a gateway, or a factory fixture. This tool is a reference for that flow and the fastest way to get a sample running. See Orbital Parameters (Satellites information) for other ways to supply orbital parameters, including compiling them into the firmware, and Pass Prediction for how to use pass prediction in your own application.

Function

The script does the following in order:

  1. Fetches orbital parameters from the Hubble API, authenticated with HUBBLE_API_TOKEN.

  2. Uses the device location from --location, or the host’s location looked up from its public IP address.

  3. Scans for up to 30 seconds for a device advertising the Hubble service UUID 0xFCA7.

  4. Connects and writes, over GATT: one record per satellite, the location, and the current Unix time from the host’s clock.

  5. Disconnects and exits with status 0 on success or 1 on any failure.

After the script disconnects, the device starts beaconing on the Hubble Terrestrial Network and turns on its satellite radio for each predicted pass.

Requirements

  1. A host computer with Bluetooth LE and internet access.

  2. Python 3.10 or newer.

  3. A device running one of the sat-dual-stack samples.

  4. A Hubble API token.

Usage Steps

The commands below are run from the SDK repository root.

1. Get an API token

Create a token by following the Hubble Platform API documentation. The tool uses it only to fetch orbital parameters; it is never written to the device.

2. Install the dependencies

Install the tool’s dependencies into a virtual environment:

Linux & macOS:

python3 -m venv .venv
source .venv/bin/activate
pip install -r tools/requirements-companion.txt

Windows (PowerShell):

python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r tools\requirements-companion.txt

3. Build, flash, and boot the device

Build and flash one of the sat-dual-stack samples by following its README.

4. Run the tool

The tool connects to the first unprovisioned device it finds. We recommend only powering one device at a time while you provision it, if provisioning multiple devices.

The tool reads two environment variables:

  • HUBBLE_API_TOKEN (required): your Hubble API token, used to fetch orbital parameters.

  • HUBBLE_TARGET_SATELLITE_IDS (optional): comma-separated satellite IDs to fetch, for example 101,102. Without it, the tool fetches all satellites. The samples store at most HUBBLE_MAX_SAT; extra satellites are dropped with a warning.

Linux & macOS:

export HUBBLE_API_TOKEN=<your-hubble-api-token>
python tools/dual-stack-companion.py

Windows (PowerShell):

$env:HUBBLE_API_TOKEN = "<your-hubble-api-token>"
python tools\dual-stack-companion.py

A successful run ends with Provisioned device successfully, and the device console then logs Next pass at with the predicted pass time.

Options

Option

Description

--location LAT LON

Device latitude and longitude, in decimal degrees. Without it, the location is looked up from the host’s public IP address.

--label NAME

Only connect to a device advertising exactly this name, for example Hubble-ESP.

-v, --verbose

Debug logging.

Accuracy

Passes are predicted for the provisioned location and time, so errors in either make the device transmit when no satellite is overhead.

  • Location. If your device will be somewhere far from the host computer, pass the device’s planned location with --location.

  • Time. The tool sends the host’s clock, so make sure it is accurate.

Troubleshooting

Message or symptom

What to do

HUBBLE_API_TOKEN env var must be set

Set it in the same shell you run the tool from.

IP geolocation failed

Pass --location LAT LON instead of relying on IP geolocation.

Device not found

Check that the device is powered, in range, and waiting for provisioning. A provisioned device stops advertising for it, so reset it first. If you passed --label, check that it matches exactly.

Provisioning Protocol

This section lays out the technical specification of the provisioning scheme. This section is not necessary to read unless you want to modify the companion tool or implement your own provisioning flow. Note that you can modify both the script and the firmware to do this in your preferred method.

After booting the device and running the tool:

  1. The sample (peripheral) does connectable advertising with Hubble service.

  2. The tool (central) scans for a device advertising the Hubble service.

  3. The tool initiates a connection with a peripheral that advertises the Hubble service.

  4. The tool writes provisioning data to the peripheral over the Hubble characteristic.

  5. The tool disconnects, and the peripheral beacons non-connectable.

  • Hubble Service UUID: 0000fca7-0000-1000-8000-00805f9b34fb

  • Hubble Characteristic UUID: 00000005-fca7-4000-8000-00805f9b34fb

The central uses write commands in the characteristic to send provisioning data to the peripheral. The command is a 2-byte header followed by a little-endian payload. See the table below.

Command

Header

Payload

Add orbital parameters

0x01 0x03

A 76-byte orbital parameter record. One write per satellite, up to HUBBLE_MAX_SAT.

Set device location

0x01 0x04

double latitude, then double longitude, in degrees (16 bytes).

Set Unix time

0x01 0x02

uint64_t Unix time in milliseconds (8 bytes).

See Orbital Parameters (Satellites information) for the layout of the 76-byte orbital parameter record and how to copy it into struct hubble_sat_orbital_params.
